# Claude Code OAuth Flow

Claude Code authenticates subscription users (Pro, Max, Team, Enterprise) via an OAuth 2.0 authorization code flow with PKCE. This page covers the flow internals, endpoints, and token lifecycle (source: gist-shubcodes-claude-code-oauth-login-2025.md, claude-code-authentication-2026.md).

## Overview

On first launch or `/login`, Claude Code opens a browser to Anthropic's authorization endpoint. The user approves access, the browser redirects back with an authorization code, and Claude Code exchanges that code for access and refresh tokens. If the browser cannot reach Claude Code's local callback server (common in WSL2, SSH, containers), a login code is displayed for the user to paste into the terminal (source: claude-code-authentication-2026.md).

## Client identity

All Claude Code installations share the same public OAuth client ID: `9d1c250a-e61b-44d9-88ed-5944d1962f5e`. This is embedded in the CLI binary, which is a Node.js SEA (Single Executable Application). The client ID can be extracted from the binary with `strings` or by scanning for `CLIENT_ID:` in the binary's UTF-8 content (source: gist-shubcodes-claude-code-oauth-login-2025.md).

## Endpoints

| Purpose | URL |
|---------|-----|
| Authorization | `https://claude.ai/oauth/authorize` |
| Token exchange | `https://platform.claude.com/v1/oauth/token` |
| User profile | `https://api.anthropic.com/api/oauth/profile` |
| Redirect (manual flow) | `https://platform.claude.com/oauth/code/callback` |

The opencode-claude-auth project uses an alternate refresh endpoint at `https://claude.ai/v1/oauth/token` (source: github-opencode-claude-auth-2025.md). It is unclear whether this is an alias or a distinct endpoint.

## PKCE flow

The flow uses S256 PKCE (Proof Key for Code Exchange) (source: gist-shubcodes-claude-code-oauth-login-2025.md):

1. **Generate verifier and challenge.** A 32-byte random `code_verifier` is generated and base64url-encoded. The `code_challenge` is the SHA-256 hash of the verifier, also base64url-encoded.

2. **Build authorization URL.** Parameters: `client_id`, `response_type=code`, `redirect_uri=https://platform.claude.com/oauth/code/callback`, `scope`, `code_challenge`, `code_challenge_method=S256`, `state` (random), and `code=true`.

3. **User authorizes in browser.** After approval, the browser redirects to the callback URL with an authorization `code` and `state` parameter.

4. **Exchange code for tokens.** `POST` to the token endpoint with `Content-Type: application/x-www-form-urlencoded` containing `grant_type=authorization_code`, `code`, `redirect_uri`, `client_id`, `code_verifier`, and `state`.

## Scopes

The standard scopes requested by Claude Code (source: gist-shubcodes-claude-code-oauth-login-2025.md):

- `user:inference` -- make model requests
- `user:profile` -- read user profile info
- `user:sessions:claude_code` -- Claude Code session management
- `user:mcp_servers` -- access claude.ai MCP server connectors

The `ant` CLI requests different scopes depending on context. Admin access uses `org:admin` (source: anthropic-cli-authentication-2026.md).

## Token response

The token endpoint returns (source: alif-claude-oauth-api-key-2025.md):

```json
{
  "token_type": "Bearer",
  "access_token": "sk-ant-oat01-...",
  "expires_in": 28800,
  "refresh_token": "sk-ant-ort01-...",
  "scope": "user:inference user:profile"
}
```

`expires_in` is 28800 seconds (8 hours). The access token prefix is `sk-ant-oat01-`, the refresh token prefix is `sk-ant-ort01-`. Tokens generated by `claude setup-token` last up to one year (source: claude-code-authentication-sept-2026.md).

`setup-token` tokens have reduced scope compared to `/login` tokens: they can only make model requests. They cannot establish Remote Control sessions or fetch claude.ai MCP server connectors. Locally configured MCP servers still work (source: claude-code-authentication-sept-2026.md).

`setup-token` enforces `forceLoginMethod` but not `forceLoginOrgUUID`, so it can mint a token in a different organization than the one a managed settings policy requires (source: claude-code-authentication-sept-2026.md).

## Token refresh

When the access token expires, Claude Code exchanges the refresh token for a new access token. The refresh request is a `POST` to the token endpoint with `Content-Type: application/json` (source: alif-claude-oauth-api-key-2025.md):

```json
{
  "grant_type": "refresh_token",
  "refresh_token": "sk-ant-ort01-...",
  "client_id": "9d1c250a-e61b-44d9-88ed-5944d1962f5e"
}
```

On a 401, Claude Code recovers in place rather than surfacing it to the user. A rejected token costs at most three API calls before failing (source: claude-code-authentication-2026.md).

## Token storage

After obtaining tokens, Claude Code stores them in the credential file or Keychain. See [[claude-code-authentication]] for the per-OS storage locations and credential file format.

## ant CLI flow

The `ant` CLI (`ant auth login`) performs a similar OAuth flow against the Claude Console rather than claude.ai. Credentials are stored under `$ANTHROPIC_CONFIG_DIR` (default `~/.config/anthropic` on macOS/Linux, `%APPDATA%\Anthropic` on Windows) in `credentials/<profile>.json`. Tokens are workspace-scoped. `ant auth status` shows the active credential source and workspace (source: anthropic-cli-authentication-2026.md).
